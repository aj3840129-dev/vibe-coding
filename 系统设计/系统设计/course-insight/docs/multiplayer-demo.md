# 多人课堂演示说明

## 结论

当前项目可以演示多名学生同时加入课堂、实时上报状态、教师端实时看到人数和学情变化。

需要注意的是：

- 默认启动时只允许本机访问：`http://127.0.0.1:8000`
- 多台设备同时加入时，需要显式开启局域网模式。
- 摄像头调用属于浏览器敏感权限。在局域网 HTTP 地址下，部分浏览器会禁止摄像头；要做真实多设备摄像头演示，推荐使用 HTTPS 部署、HTTPS 内网穿透，或配置本地 HTTPS 证书。

## 本机多窗口演示

适合课堂答辩兜底：

1. 教师端打开 `http://127.0.0.1:8000`，以教师身份登录并开设课堂。
2. 复制课堂码。
3. 再打开多个无痕窗口或不同浏览器窗口。
4. 分别用不同学生姓名登录并加入课堂。
5. 教师端可以实时看到多个学生状态、事件流和课堂复盘数据。

这种方式能证明后端支持多学生会话和实时同步，但不能证明多台真实设备的摄像头同时接入。

## 局域网多人演示

适合让同学手机或电脑加入同一节课：

```powershell
cd E:\系统设计\course-insight
$env:LAN="1"
npm start
```

启动后终端会打印局域网访问地址，例如：

```text
http://192.168.1.23:8000
```

同一 Wi-Fi 下的学生设备访问这个地址，选择学生身份登录，输入教师端课堂码即可加入课堂。教师端会通过实时数据流看到这些学生的加入、反馈、页面状态和自动遥测数据。

## 真实摄像头多人演示边界

如果学生设备通过 `http://192.168.x.x:8000` 访问，浏览器可能因为不是安全来源而拒绝摄像头权限。这不是项目逻辑问题，而是浏览器安全策略。

推荐答辩说法：

> 当前本地版已经完成多人课堂链路、实时数据同步、摄像头采样逻辑和后端学情推理。真实多设备摄像头演示需要把服务放到 HTTPS 环境，或使用 HTTPS 内网穿透。否则可以用本机 localhost 摄像头演示识别过程，用局域网多设备演示多人实时同步。

## 满分展示顺序

1. 教师开课，生成课堂码。
2. 两到三名学生从不同窗口或设备加入。
3. 学生端开启自动监测，教师端观察状态实时变化。
4. 学生切换页面、失焦、长时间不操作，教师端出现依据说明。
5. 能授权摄像头的设备开启摄像头，展示人脸/画面信号上报。
6. 教师端触发传感器进入/离开，展示教室人数变化。
7. 学生向 AI 助教提问，展示外部 AI 或本地兜底回答。
8. 教师结束课堂，展示复盘图表和课堂数据总结。
